## Frontend Edit Rules

- **Simplest CSS solution first** — pick one approach, apply it, let the user judge. No trial-and-error loops.
- **Theme-aware** — if `.project/project.json#theme` exists, use its tokens. Check before introducing arbitrary values.
- **Verify structural edits** — after layout/DOM/position/responsive changes, use visual snapshot / browser verification to check. Skip for cosmetic-only edits.
- **Verify data first** — before building UI on a data source, inspect the actual shape/availability.
- **Screenshot-verify** — when user shares a screenshot with edit instructions, capture screenshot of current state, compare, make edits, and re-screenshot to verify.
- **Inspect refs → /dev-inspect** — a pasted bracketed element ref (`[src/components/Button.tsx:42 …]`) plus an edit request: invoke the `dev-inspect` skill — don't edit ad hoc.

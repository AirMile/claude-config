### Added

- **Global `CLAUDE.md` § Skill Feedback now has a proactive half: self-observed skill friction is raised as a proposal after a run.** (`local/CLAUDE.md.base`, mirrored verbatim into the live `~/.claude/CLAUDE.md`.) The section previously covered only user-initiated feedback ("if feedback concerns a skill, edit its SKILL.md"), so the common case — the executor itself noticing during a run that a modal was auto-decidable, an instruction was ambiguous, or a failure path was missing — had no home and evaporated with the session. Improving skills is part of this user's actual work, so the observation is now treated as a deliverable rather than a stray thought. A Fable second opinion on the first draft rejected three of its choices: a new top-level `## Skill Self-Improvement` section (two sections answering the same runtime routing question — "skill defect → where does the fix go?" — forces a reconciliation at runtime; folded into § Skill Feedback as its second bullet instead), a standing "always commit in the claude-config repo" line (a direct collision with the harness rule that commits happen only when the user asks, made worse by the target repo differing from the session cwd), and the draft's ~34-line length for an always-loaded file (cut to 5 bullets: the two "watch for" enumerations were collapsed inline, and the cross-pipeline `dev-*`↔`game-*` sync line dropped as already covered by project `CLAUDE.md § Rules for Changes`, which any claude-config edit loads anyway). It also flagged that the approval gate sat only in a heading parenthetical while the opening line said "part of the job" — that gate is now its own bolded bullet stating that noticing a defect is never authorization to fix it. Trigger discipline is observed-only, after the run's report, never mid-run (so it cannot license mid-run improvisation against § Command Execution Rules' "follow skill instructions exactly"), silent when nothing concrete was observed, capped at 2-3 cited points. Routing splits trivial fixes (wording, a hedge, a wrong default → direct edit) from structural ones (phase order, lazy-loading, agent/model, handoff → `/core-audit <skill> "<observation>"`, whose evidence pass and plan-mode gate a single run's friction should not bypass). Considered and rejected (don't re-add without a new reason): moving the trigger itself into `shared/OUTPUT.md`'s report grammar as an optional FRICTION line. It first read as more enforceable against compaction, but a second Fable review killed it on its own terms — an optional slot in 42 report templates invites ritual filling, which is exactly the failure the "silent when nothing observed" clause exists to prevent, and a prose-shaped line also violates § Report Block's "values are data, not sentences". The same review rejected a proposed swap of "an ambiguous or skippable instruction" for core-audit's skip/weaken/improvise vocabulary: that classification is post-hoc against a run transcript (`core-audit/references/trace-analysis.md`), which trace mode re-derives on its own, so pre-shaping the note buys nothing while spending jargon in an always-loaded file — the shipped phrase names the cause a running model can actually notice.

- **New `core-explain` skill (v1.0.0) — a brief, opinionated explanation of one topic, user-invoked only.** A plain "explain X briefly" prompt already inherits tone from `~/.claude/CLAUDE.md` (direct, opinionated, target language) but nothing constrains length or shape, so it drifts back to intro-body-recap essay form. The skill earns its slash command through exactly three additions, stated as a rationale block inside `SKILL.md` so a later `/core-audit` does not fatten it: a hard ~250-word ceiling (hard max 300), a four-rule form constraint that keeps free form steerable without headings (no preamble — the first sentence IS the core claim; fixed order what → why it matters → one pitfall; a mandatory `Opinion:` closing line; no bullets under 3 parallel items), and two deliberately bounded relaxations of standing global rules. Those relaxations are the load-bearing part and are written with explicit precedence, since without it the global rule silently wins: (1) `§ Factual Accuracy`'s blanket "never assert a verifiable fact from memory" is narrowed to a single testable trip-wire — look the source up first only when the explanation would state a specific number, version, price, date, or the existence/status of a named product feature — because applied unrestricted it makes every short explanation cost a lookup round; the per-subject routing (`claude-api` skill / context7 / official page, source named inline) is **not** relaxed. (2) The "unclear instruction → ask, don't guess" default is narrowed to state-the-reading-and-proceed, with a question only when two readings produce materially different explanations, because asking by default makes every fuzzy invocation a two-turn interaction. Explanation depth and output language are read at runtime via `shared/EXPLANATION.md` and `shared/LANGUAGE.md`, never hardcoded. Deliberately carries no PHASE structure and no ASCII report (conversational output skill — same exemption as the thinking skills; precedent `content-rewrite`), no references, no agents, and no `reads:`/`writes:` — it touches no shared state. The `description` is kept slash-bound and trigger-narrow so the skill does not auto-fire on an incidental "explain this" mid-coding-session, where a truncated 250-word answer is exactly wrong; `disable-model-invocation` was rejected for that job since it would also kill `/core-explain` itself. A Fable second opinion on the design rejected the originally-chosen "free form + word budget only" (word budgets alone do not steer shape — the ordering rule does the work) and flagged that `core-*` is infra/meta in this repo while `content-*` is prose production; the `core-` prefix is a conscious user choice, noted here so it reads as a decision rather than a slip.

  **Follow-up in the same release (v1.0.0 → v1.1.0): made portable to Claude Cowork / claude.ai chat, plus a new `scripts/export-skill.sh`.** The skill was written on the assumption that the Claude macOS app reads `~/.claude/skills/` — true only of its Code tab. The Home tab (chat and Cowork) reads a server-synced plugin directory (`~/Library/Application Support/Claude/local-agent-mode-sessions/skills-plugin/…`) whose `manifest.json` marks every entry `"creatorType": "anthropic"`; hand-placing a skill there is overwritten on sync, and the supported route is a ZIP upload via Customize → Skills whose archive root is the skill folder. Since that host has no `CLAUDE.md` and mounts the real home elsewhere (`$HOME/mnt/`), the skill's two `skills/shared/*.md` pointers resolved to nothing there. Four changes make one file work on both hosts: (1) § 2's shared-file pointers become a resolution ladder — a reachable `CLAUDE.md` (project, then `~/.claude/`, then a best-effort `$HOME/mnt/.claude/` probe for sandboxed hosts) → the host's personal instructions → documented defaults (`Intermediate`, and the language the user is writing in), with the level table's short form inlined; the level and language are still never hardcoded, per `shared/EXPLANATION.md`'s authoring rule. (2) Both relaxations are reworded conditionally ("where a global factual-accuracy rule exists…"), since on a host without a global instruction file they relax rules that do not exist — a new § Host caveat states plainly that they are inert there and that the length ceiling plus the form rules are what carry the skill, so a future audit does not re-absolutise them. (3) § 4 gains a no-lookup-available branch: when no source can be checked, say so and mark the claim unverified rather than falling back to a confident answer from memory — an unavailable tool is not permission to guess. (4) A drift warning at the top of `SKILL.md` plus a version stamp, because the upload is a copy that cannot symlink: `CLAUDE.md § Skill Feedback` routes every behaviour tweak into this file, Claude Code picks it up instantly, and the uploaded copy would keep serving the old text with no error. New `scripts/export-skill.sh <skill>` packages `skills/<skill>/` into `dist/<skill>.zip` with the folder as the archive root (a ZIP with `SKILL.md` at the root does not register), warns when `description` exceeds claude.ai's 200-character limit, and prints the version and next step. It exports **verbatim** — a Fable second opinion rejected the first draft's frontmatter-stripping step as a speculative fix for a rejection never observed (extra keys are expected to be ignored); reducing to `name` + `description` is documented as the first thing to test if an upload is ever refused, not a standing transform. `dist/` added to `.gitignore`.

- **`dev-ship`/`game-ship` define interview: an "Assumption Block" replaces the old context-echo, pre-chewing the problem-space instead of always asking fully open.** (`dev-ship` v0.47.0 → v0.48.0, `game-ship` v0.9.4 → v0.9.5.) The interview posed every dimension as an open question even when the seed, the backlog card, or an upcoming card already answered it. Root cause, per a Fable second opinion: two separate gaps, not one. First, `project-seed.md`'s full markdown (§ Out of Scope, § Open Decisions, § Key Features) was never loaded before PHASE 1a — only a `project.json#seed.pitch` fragment reached the interview; the full seed arrived only at PHASE 2's Seed Alignment Check, after the interview was already over. Second, the pre-interview "context echo" (`phase1a-interview.md`) was capped at 2-3 lines and framed as facts already known, never as inferences drawn from them — it recapped, it didn't pre-chew. What was _not_ a gap, contra the first-draft diagnosis: `context-load.js`'s `define` profile already emits every backlog card, and `open-items` already loads in the same PHASE 0 batch — that fuel existed, just scoped only to PHASE 2's backward-looking Backlog Impact Check, never to sharpening non-goals up front. Fix: new `shared/QUESTIONING.md § Assumption Block` — up to 5 problem-space bullets (goal, scope boundary, non-goals, success criteria), each citing its source (seed section / backlog card / learning), rendered once before the opening question; a dimension covered by a non-struck bullet is not re-asked. Cite-or-ask is absolute — an uncited claim is never rendered as a bullet, it falls back to an open question. Non-goal bullets are cited-only, never inferred from silence (a wrongly-assumed goal surfaces at verify; a silently-cut scope never does). Source precedence on conflict: backlog card > seed > learnings, since the seed only updates on approved drift and can present stale scope as current fact. `dev-define/workflow.md` PHASE 0 §4 gains an unconditional `SEED_CONTEXT` load (net token cost ~0 — PHASE 2's Seed Alignment Check already forces that same Read later in the same turn; this only moves it earlier) and broadens `open-items`'s stated purpose to feed the new bullets too. The tone rule "no solution proposals" is unchanged for architecture/files/tech — the block is a stated, scoped exception for problem-space claims only, never for the solution space. To keep the Seed Alignment Check from becoming tautological (rarely detecting drift against the document the interview was anchored on), its comparison basis moves to the user's actual answers/REQs, and any bullet the user struck whose source was the seed is now a first-class drift candidate in its own right. Considered and rejected on the same Fable review: a PHASE 2 architecture seam-check against dependent upcoming cards (speculative generality — designing for requirements a dependent card hasn't even stated yet); instead the vooruitblik stays a single informational `Upcoming: {name} depends on this feature` line in the existing `## Backlog impact` gate section, no new gate section, no architecture concession. Also considered and rejected: drafting the full concept-REQ list up front with the interview purely corrective (collides with PHASE 1b's own REQ-checkpoint as a second review surface, and REQs sit too close to the solution space — anchoring there is harder to walk back than a problem-space bullet). `game-define/SKILL.md` and both `phase1a-interview.md` copies mirror the same four changes (seed load, open-items scope, Assumption Block call, Seed Alignment reversal) — Godot-specific content untouched.

- **`dev-ship`/`dev-manual` manual round: small in-scope tweaks now get fixed in the ship itself instead of always offloading to a TWEAK card.** (`dev-ship` v0.46.0 → v0.47.0, `game-ship` v0.9.3 → v0.9.4 for a discipline-sync mirror.) The existing inline-fix exception in `phase-3-manual-finalize.md § Findings ledger + routing` was too narrow to ever fire in practice — it required the _entire_ ledger to be ≤2 findings, all "cosmetic (styling/timing/copy)". Anything else, including a 1-file/2-line behavioral fix made while the app is still running and the user is watching live, went through the full `/project-todo` → `/dev-tweak` round-trip (a fresh session re-resolving the repo, re-locating code just written, re-launching the app, a separate commit and card-archive write) even though `phase-3-manual-finalize.md`'s own regression re-check already runs the full test suite plus typecheck/lint after any PHASE 3 edit. A Fable second opinion on the first draft of this change rejected two of its three proposed elements: a new "micro band" section in `shared/TWEAK-DISCIPLINE.md` (that file is also loaded by `/dev-tweak`, `/game-tweak`, and `/dev-inspect`, none of which could use it — the change stayed local to the ship references instead) and a `≤10 changed lines` criterion (redundant with `DEBUG-LADDER.md`'s existing tier-1 definition, and the only non-file-shaped, non-pre-checkable unit in the whole gate); it also flagged that the real gap was the inline path's total absence of bookkeeping, not its narrowness. Net changes: the routing table's inline row now reads "DEBUG-LADDER tier 1 (symptom + cause both visible) and in-scope" instead of "cosmetic", drops the ≤2-findings whole-ledger requirement in favor of a per-finding **partition** (qualifying findings fixed inline, cap 3; the rest still route through the offload flush, unchanged), and the inline path itself imports the same `tweakAttempts`-counted 3-attempt polish-loop cap (with a mid-loop "re-file as a fail-class finding" escape and the same "Tweak not converging" `AskUserQuestion` ladder) that `fix-round.md`'s cosmetic-tweak bullet already had — closing the exact "no round bookkeeping" gap the inline path used to have relative to its sibling. The partition is offload-first by construction: every card is created and every offloaded item's `offload` field is written before the first inline `Edit`, so a crash mid-pass leaves a distinguishable state instead of an ambiguous one, and the offload flush now skips any item that already carries `offload` on a resumed pass (idempotency). `scripts/ship-checkpoint.js`'s `manualLedgerResolved()` is tightened to match: a `"tweak"` verdict only counts as resolved when the item also carries `offload` (two new `scripts/tests/run.sh` cases cover both sides), closing the gap the partition would otherwise open — previously the mere string `"tweak"` was enough regardless of whether a card existed. `fix-round.md`'s tweak-class `AskUserQuestion` gains a "Fix inline now (Recommended)" option ahead of "Offload"/"Park" when every remaining finding qualifies for the band, and its cosmetic-tweak polish loop no longer requires being "the only finding still open this round" — only that no sibling finding this round is fail-class. `game-ship` mirrors only the inline-row widening and the `tweakAttempts` cap (`phase-3-playtest.md`, `fix-round.md`) — not the partition, since game's routing table has no separate offload row to partition against (offload lives inside its fix-round instead), so a 1:1 mirror there would have been a structural rebuild outside this change's scope.

- **`dev-tweak` v1.13.0: lane routing — replaces two half-overlapping model-selection mechanisms with one first-match decision table, wired into the Fable Second Opinion Consult.** `SKILL.md:131-136`'s "conditional plan mode" (two vague triggers: unclear root cause, or > 2 files) and PHASE 3 Tier-2's "Escalate — design this properly with Opus" option were two separate attempts at the same job — deciding how much process a tweak's design gets.

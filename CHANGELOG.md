- **Learnings gain a `paths[]` anchor — language-neutral relevance matching on file paths.** Optional new field on `project-context.json#learnings[]` entries (0-5 repo-relative source paths, capped by the script; NOT part of the dedup key): summaries are often written in the runtime language (Dutch) while queries, slugs, and filenames are English, so keyword overlap under-matched exactly the entries that mattered. `learnings-search.js` gains a `--paths` flag on `load`/`search`: caller paths reduce to tokens (extension stripped, camelCase/kebab/snake split, generic segments like `src`/`components` dropped), score +2 per overlap with an entry's `paths[]` tokens (capped at 3), and also join the keyword pool so pre-`paths` entries whose summary names the file benefit too. `learnings-write.js` passes `paths` through on `append` (cap 5) and unions most-frequent paths into the consolidation merge scaffold. Schema documented in `LEARNING-WRITE.md § Writer Append Protocol → Paths` + `DASHBOARD-CONTEXT.md`; scoring in `LEARNINGS-LOAD.md § Relevance model`; two new tests in `scripts/tests/run.sh` (path-anchor ranking on a Dutch-summary fixture; append passthrough + cap).

- **`learnings-write.js`: new `enrich` command — patches `tags[]`/`paths[]`/legacy-schema migration onto EXISTING `learnings[]`/archive entries, distinct from `append`'s dedup-and-insert path.** `echo '{"patches":[...]}' | learnings-write.js enrich <root> [--target active|archive:<file>]`. Each patch identifies its target via content-based `match` (raw `key`/`textEquals`/`noteEquals` for a legacy `{type,key|text|note,source}`-shaped row, or `feature`+`type`+`summaryEquals` for a current-schema row) — never positional/index matching, since `consolidate` already reorders/removes rows. Idempotent: a repeat run of a legacy migration (whose first run already deleted the raw `key`/`text`/`note` field the match tiers look for) falls back to identity matching on the patch's own `feature`+`summary` and reports `alreadyApplied` rather than re-migrating or erroring. Reports `{ patched, alreadyApplied, notFound, ambiguous }` — `notFound`/`ambiguous` are non-fatal and explicit, never a silent wrong-entry write. Bypasses `append`'s dedup entirely (the `match` resolution IS the uniqueness guarantee — running Jaccard here would risk collapsing two distinct migrated entries). Three new tests in `scripts/tests/run.sh` (tags+paths patch leaves a control entry untouched; legacy-key migration produces a schema-conformant entry + a second identical run is a no-op; an unmatched patch is reported, not swallowed).

- **`/project-app install-app` now covers Windows too — same "one real app, no background daemon to babysit" outcome, Task-Scheduler-backed** — `skills/project-app/references/install-app-windows.md` is the PowerShell counterpart to `install-app-macos.md`. Since Windows Task Scheduler can't cleanly replicate `KeepAlive`'s any-time crash-restart for a detached console-free process, the trigger is `AtLogOn` instead (accepted trade-off — `node --watch` still handles its own file-change restarts; a mid-session crash needs a fresh login, not a resilience gap worth a foreground-task workaround for a small local dev server). The task runs a small VBS launcher (`wscript.exe`, GUI-subsystem host + `Run`'s windowstyle `0`, so login shows no console flash) that starts `node --watch serve-backlog.js` with `BACKLOG_IDLE_SHUTDOWN_MS=0` baked in via an absolute Node path (Scheduled Tasks don't reliably inherit an interactive shell's PATH). That design needed **two** Dock icons (a launcher `.app` to start the server on demand, plus the installed PWA for the actual window) because a PWA can't start itself — clicking the launcher visibly "opened another app" with its own, easily-stale icon. `install-app` (`skills/project-app/references/install-app-macos.md`, replaces `install-launcher-macos.md`) installs a macOS **LaunchAgent** (`com.claude-config.project-board`, `RunAtLoad` + `KeepAlive`, `BACKLOG_IDLE_SHUTDOWN_MS=0` so the server's own idle-shutdown never fights `KeepAlive`'s auto-restart) that keeps `serve-backlog.js` running in the background, then walks through installing/re-pinning the **PWA** as the single Dock icon — a real standalone `.app` bundle with native minimize/restore. The doc also removes the old launcher `.app` and its Dock pin as part of running it. `/project-app stop` now `launchctl bootout`s the agent before killing the port (a bare `kill` would just bounce back under `KeepAlive`); the bootout is a no-op when no agent is installed, so `stop` stays safe either way. `lib/pwa-register.js` gained a small "Install app" button (via `beforeinstallprompt`) so re-installing after an icon change is one click instead of hunting the address-bar icon. Electron/Tauri were evaluated for a "real app" and rejected — both would add a build toolchain (`package.json`/Rust) to a repo that deliberately has none, for what's fundamentally a local static page.
